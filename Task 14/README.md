# Task 14 - Explain every person's risk (CortexHR, Phase 3, Day 14)

Scores all **430 active employees** with the shipped **`attrition-v2`** model from Task 13 (no new model is trained) and gives each person a
risk score, a risk band and **three plain-English reasons** derived from real SHAP values. Every row is marked for human review.
**This is decision support: SHAP explains what the *model* does, not why a person might actually leave.**

> These predictions are estimates generated by a machine learning model. The explanations describe factors influencing the model's prediction,
> not proven causes of employee behaviour. Every result requires human review before any HR action.

## 3. Model version (verified before use)
`attrition-v2` = **`CalibratedClassifierCV`**: 5 calibrated members, each = Task 2 pipeline (cleaning, imputation, scaling, one-hot) -> balanced `LogisticRegression` -> sigmoid calibration; the probability is the **average of the 5 members**.
Task 13 chose this over LightGBM by a rule fixed beforehand. Checks in `model_loader.verify_model`: version string, estimator type, class order `[0, 1]` (column 1 = leaves), 5 members, 33 features in training order, scikit-learn 1.8.0 = training version.
Out-of-fold quality (Task 13): ROC-AUC 0.711, PR-AUC 0.310, calibration error (ECE) 0.020. **Modest ranking power on a small simulated dataset - see limitations.**

## 4. Scoring
Task 13's own `predict_attrition` on the Task 13 scoring table. Probabilities **0.006 - 0.491, mean 0.128, median 0.108** (all within 0-1, none missing, ids unique and aligned one-to-one). The scored value is the probability of **leaving** within 12 months.

## 5. Risk bands - official `risk_bands()` helper (unchanged, `cortexhr_helpers.py`)
Rule from the helper: **High = top 10% of scores, Medium = next 20%, Low = the rest.** It is **rank-based**: the cut-offs are the 90th and 70th percentiles of the batch (here **0.2385** and **0.1486**), so a band says where someone sits among these 430 people, not an absolute chance.
Result: **High 43, Medium 86, Low 301** (identical split to the official sample). Values equal to a cut-off go to the higher band (`>=`). Bands use the *unrounded* probability, so two people can both show 0.149 yet be in different bands (EMP-0725 Medium, EMP-0420 Low in the sample file). The helper would label a missing score "Low" silently, so NaN is rejected before banding.

## 6. SHAP method (and why)
| question | answer |
|---|---|
| Which explainer? | **`shap.KernelExplainer`** on the complete fitted model. attrition-v2 is **not** a tree model, so TreeExplainer does not apply. |
| Why not LinearExplainer? | The output is the mean of 5 sigmoids; `sigmoid(mean of 5 margins)` differs from the real prediction by up to **0.081**, so explaining the average margin would explain a different function than the one that scored people. |
| Pipeline-aware? | Yes. Coalitions mask **whole raw input features** (33) and run the *entire* pipeline (cleaning, imputation, scaling, one-hot) each time. No one-hot fragments, no training-serving drift (an encode/decode round trip reproduces predictions exactly). |
| Scale | **Probability units.** `prediction = base value + sum of contributions` (checked for all 430: max error 5.4e-10). 0.01 = 1 percentage point. Positive = raises the predicted risk, negative = lowers it. |
| Reference (base value) | average prediction over a fixed random background of 40 of the 430 employees = **0.1288** (about the cohort mean 0.1277). Contributions mean "compared with a typical active employee". |
| Settings | 1,500 sampled coalitions per employee, global NumPy RNG seeded per employee (42 + row), background seeded: **reproducible**. Cached by fingerprint. About 12 min on one CPU core. |
| Is it stable? | Cross-check on 12 employees against 6,000 coalitions: **12/12 identical top-3 sets**, max coefficient difference 0.0015 (below the 0.005 materiality threshold). A *different background sample* does change things somewhat (top-3 overlap about 0.94 in an earlier test), so contributions are relative to the chosen reference group. |
| Faithfulness check | For 429 employees: replacing the #1 risk-raising feature by its typical value lowered the model's prediction in **428** (99.8%). |

## 7. Top-three reasons
`reason_generator.select_reasons`, from the real SHAP row of each employee:
1. Only **eligible** features (section 8) and only contributions of at least **0.5 percentage points** count (`MATERIALITY`).
2. **Risk-raising** drivers first, strongest first (not the largest absolute value: a big negative value is never a "risk reason").
3. **At most one reason per theme** (pay, raises, promotion, engagement, workload...), so reasons never repeat or contradict (e.g. "few raises" and "recent raise").
4. If fewer than three raising drivers exist, the strongest **risk-lowering** ones fill the slots and say "lower-than-average"; if still short the slot reads *"No further factor with a notable influence..."* (never invented).
Result: **386 employees have three risk-raising reasons, 44 have at least one risk-lowering reason, 1 has no risk-raising reason, 0 slots are empty.**

## 8. Plain-English translation and sensitive data
Every one of the 33 model features has a policy entry (`reason_generator.FEATURE_POLICY`, saved as `reports/internal/feature_policy.csv`). Sentences are hedged ("is contributing to a higher-than-average predicted attrition risk"), never say someone will leave, never use "flight risk", and imply no disciplinary action.
| Never named in a reason (still used by the model) | Why |
|---|---|
| `total_experience_years` | **possible** proxy for age (not measurable: the data has no age field; see section 15) |
| `highest_education` | possible proxy for socio-economic background |
| `work_location`, `commute_distance_km` | region / home location; possible proxy for community background |
| `unpaid_leave_days_6m`, `paid_leave_days_6m`, `avg_unpaid_absence_days_3m` | can reveal health, family or religious circumstances |
The model has **no** name, gender, age, religion or caste columns, so none can appear. **No fairness audit across protected groups was possible or is claimed**: the employee data contains no protected attribute to audit against. Reasons contain no names or ids (checked by `validation.py`).
* **Tenure:** always worded neutrally in either direction: *"Recorded length of service (12 months) is contributing to a higher-than-average estimate in this model. Length of service alone does not indicate an intention to leave."* New joiners are never called high-risk.
* **Missing values:** named only when the gap is itself an HR fact ("No promotion / no pay raise is recorded since joining"); other gaps are data gaps, not findings, and are not named.
* **Department / role:** worded as a group-level pattern, "not a finding about this individual".
* **Extreme attendance change** (30+ points) is flagged as possibly a data error, not as behaviour.
* **Transparency about what is hidden:** the excluded features carry on average **6.9 percentage points of absolute SHAP per employee**, and for **18%** of employees the single largest contributor is an excluded feature. `total_experience_years` is the **#2 most influential feature overall** (full review in section 15). The three reasons therefore are **not the full story**; `model_note` says so, and `suppressed_abs_contribution` is in the internal report.

## 13. Prediction, contribution, correlation, causation
* **Prediction:** the model's estimated probability (here 0.006-0.491) that an employee with these records leaves within 12 months. Not a certainty and not a decision.
* **Feature contribution (SHAP):** how much a recorded value moved *this model's* prediction away from the reference group's average. A bookkeeping of the model's arithmetic.
* **Correlation:** in the training data, people with such values left more or less often. The model uses patterns, not reasons.
* **Causation:** whether a factor *makes* someone leave. Nothing here shows that. A low engagement score pushing the prediction up is not evidence that engagement caused anyone to leave; a pay raise would not necessarily change anything. **SHAP explains the model's behaviour, not the actual reasons an employee might leave.**

## 14. Limitations
* **Modest model on small simulated data:** ROC-AUC about 0.71, 349 leavers in training; individual predictions are uncertain. Top-10% precision in Task 13 was about 33%.
* **Rank-based bands:** "High" always means the top 43 of this batch, even if everyone were low risk in absolute terms.
* **Reasons are relative to the average employee** and, for low-risk people, can still list "higher-than-average" factors while the overall risk is very low (e.g. EMP-0179 at 0.6%).
* **Hidden inputs:** possible age/background proxies and leave data influence scores but are never named (section 8). Job level and tenure may also correlate with age; the model's use of `total_experience_years` should be reviewed by HR/legal (section 15). Task 14 cannot change attrition-v2.
* **Kernel SHAP is a sampling approximation** (stable here, verified) and assumes independent features when masking; contributions depend on the reference group.
* **Group-level reasons (department, role) describe training-data patterns, not the person.**
* The employee-level reasons are not recommendations; wording avoids actions. Discussion with the employee should be voluntary and supportive.
* Version coupling: the pickle needs scikit-learn 1.8.x; Task 13's open items (O1, O2) and its source-shortcut limitation still apply.
* No API code exists in the repository, so nothing was added to an API.

## 15. `total_experience_years`, and Task 13 left unchanged
<!--TOTALEXP:START-->
## `total_experience_years` review

**Question.** The model's #2 most influential input is `total_experience_years`. It is never named in an employee's reasons as a precaution, because it could act as a proxy for age (which cannot be measured here). Is that policy enough, and what does the evidence show?

**What the data can and cannot show.** The workbook has **no age, date-of-birth or gender column for employees** (all 26 sheets scanned), so a link to age is **not measured here**. The concern rests on how the variable is built: experience accumulates over a working life. Nothing below demonstrates age discrimination, and nothing rules it out.

| evidence (real attrition-v2 model, 430 employees) | value |
|---|---|
| Importance rank by mean absolute SHAP (of 33) | **2** (2.97 percentage points; 8.9% of all SHAP) - after job level (3.42), before length of service (2.87) |
| Direction | more recorded experience -> **higher** model risk (rank correlation of value and contribution 0.98) |
| Correlated with (Spearman, scoring data) | job level 0.65, annual pay 0.59, tenure 0.50, previous employers 0.16 |
| Data quality | 17 employees record **less total experience than their tenure** (range 0.0-31.8 years, median 8.6) |
| Logistic coefficient per standard deviation, 5 ensemble members | 0.76, 0.44, 0.75, 0.50, 0.40 (all positive, but varies by almost a factor of 2) |
| Marginal signal in the training table (2,379 rows, 349 leavers) | AUC **0.49** - alone it does **not** separate leavers |
| Sign once tenure and job level are held fixed | +0.33 per SD, bootstrap 95% interval [-0.00, 0.59] - the lower end touches zero |
| If it were NOT suppressed | in the top-3 risk-raising drivers of **128** employees, the single top driver for **65** |
| All 7 suppressed features together | 6.9 percentage points of absolute SHAP per employee; the single largest contributor is a suppressed feature for **77** employees (18%), **55** of them `total_experience_years` |

**Why leaving it out of the explanations does not remove its influence.** The reasons are a post-processing step on top of the model: attrition-v2 still receives the feature and still uses it to compute every score and band. What-if on the real model (the model is untouched; only the input is altered): setting everyone's experience to the cohort median changes the predictions by **3.0 percentage points on average** (up to 16.0), moves **82 employees to a different band**, and keeps only **28 of the 43** highest-risk people in the High band. It is the 3rd most influential input by this measure as well. So the scores and High-risk list partly depend on it, while the displayed reasons do not mention it.

**What this means.**
* The suppression is a **presentation safeguard, not a fairness fix.** It stops the report from saying "experience raises risk", but it cannot undo the feature's effect on who is ranked High.
* Its contribution is **statistically fragile**: no marginal signal, a positive sign only after conditioning on tenure and job level, a bootstrap interval touching zero, and member-to-member variation. It looks like a statistical correction for tenure and level rather than a robust attrition signal. That is evidence about *predictive stability*, not about fairness.
* Job level (#1) and tenure (#3) are also correlated with experience (and plausibly with age); both remain nameable (tenure with the mandated neutral wording). The exclusion list is therefore **not a complete age-proxy control**.
* Not done and not claimed: no group-fairness audit (no protected attribute exists for employees), no age analysis, no retraining. A defensible next step for Task 13/HR/legal is to retrain **without** `total_experience_years` and compare ranking quality and who moves bands, and to fix the 17 inconsistent records. Task 14 must not change attrition-v2.
